# Nilton City Portfolio Constitution

## Core Principles

### I. Verified public evidence
Published activity MUST come from an identified public GitHub snapshot. Contributions MUST NOT be called commits. Decorative geometry MUST NOT imply activity that did not happen. Private repositories and credentials MUST never be bundled.

### II. Playable and accessible
Exploration MUST support keyboard and touch. Every project MUST also be reachable without playing. Reduced motion MUST disable automatic camera movement. Dialogs MUST have accessible names, focus handling and an Escape exit.

### III. Small static architecture
Use static HTML, CSS and browser JavaScript. Add a graphics dependency only when it enables the requested city. Avoid a backend, account system and persistent personal data. Public data MUST remain usable without a live API connection.

### IV. Functional verification
Before publication, verify data mapping, bounds, project links, controls, desktop and narrow layouts. Checks MUST cover actual data transformation and navigation rules. Record browser or publication limitations accurately.

### V. Cohesive original identity
Honor the user's purple/pink city reference and explorability. Use original geometry and graphics. Keep text readable. Profile and site MUST use the same identity and factual descriptions.

## Constraints
No secrets or personal contacts inferred from private sources. Publish only confirmed identity and public project evidence. Date snapshots. No fabricated employment, skill ratings or testimonials.

## Development Workflow
Complete spec, plan and tasks before implementation. Implement tracked tasks only. Review against the constitution before publishing. Document exceptions in the feature specification.

## Governance
Amendments require a reason and semantic version bump. Major changes remove or redefine principles; minor changes add principles; patches clarify. Every delivery checks these principles and reports violations.
